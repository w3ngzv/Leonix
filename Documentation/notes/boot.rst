==============
从复位到 main
==============

**启动代码** (startup code) 是处理器复位之后, C 语言的 main() 开始执行之前
运行的一段程序. Leonix 的启动代码是 arch/avr/start.S, 约 80 行 AVR 汇编,
由提交 8ef65de (2026-10-08) 加入, 此后未再修改. Caterina bootloader 交给
应用时的机器状态另见 ../booting.rst, 本文只引用其结论.


C 代码依赖的前提
================

avr-gcc 编译出的代码默认下列四项前提已经成立, 而处理器复位本身一项也不
保证:

- 栈指针 SP 指向一块可用的 SRAM. 函数调用要把返回地址压栈, 局部变量也
  大多存放在栈上.
- r1 为 0. avr-gcc 把 r1 当作常数 0 使用 (``__zero_reg__``), 生成的代码
  不会在每次使用之前重新清零.
- 有初值的全局变量 (``.data`` 段) 在 SRAM 中已经具有初值.
- 没有初值的全局变量 (``.bss`` 段) 为 0, 这是 C 标准对静态存储期变量的
  规定.

以 init/main.c 中的 ``uint16_t blink_half_period = HZ / 2;`` 为例. 初值 500
是程序的一部分, 烧录时写入 Flash; 变量本身则位于 SRAM 地址 0x0100, 而 SRAM
断电后内容丢失, 上电时的内容不确定. 若没有代码把 500 从 Flash 复制到
0x0100, main() 读到的就是一个任意值. 在 PC 上, 这些工作由操作系统的程序
加载器与 C 运行库中的 crt0 完成, 编写普通程序时因而无从察觉.


中断向量表
==========

**中断向量表** (interrupt vector table) 是 Flash 起始处的一张跳转表. 中断
发生时, 处理器按中断的种类跳到表中固定的位置, 例如 Timer1 比较匹配 A 中断
对应字地址 0x0022 (数据手册表 9-1). ATmega32U4 共有 43 个向量, 每项 4 字节,
恰好容纳一条 ``jmp`` 指令. 第 0 项是复位向量, Caterina 跳转到 0x0000 时
执行的就是这一项.

start.S 用汇编器的 ``.irp`` 循环生成第 1 至 42 项. 每一项跳向符号
``__vector_N``, 而每个 ``__vector_N`` 都先被定义为指向 ``__bad_interrupt``
的**弱符号** (weak symbol). 弱符号是链接器允许被同名普通符号取代的定义.
arch/avr/switch.S 定义了普通符号 ``__vector_17``, 链接时该符号取代了弱定义,
表中第 17 项因此跳到上下文切换代码, 其余 41 项仍然跳到 ``__bad_interrupt``.
这一结果可以用 ``avr-nm -n leonix.elf`` 核对: 41 个向量的地址都是 0x120,
类型为 W, 即弱符号; ``__vector_17`` 位于 0x122, 类型为 T.

这种写法使新增中断处理程序时无需修改 start.S, 只要在任一源文件中定义名为
``__vector_N`` 的全局函数即可. avr-libc 的 ``ISR(TIMER1_COMPA_vect)`` 宏
展开后得到的也是 ``__vector_17`` 这个名字. 提交 104f2cc 就是用 C 的
``ISR()`` 实现节拍中断的, 弱符号的覆盖由此在板子上得到确认 (b56d672),
之后 d4fcdd3 才把该向量改为汇编.

``__bad_interrupt`` 是一条跳回自身的指令. 处理器进入中断时会自动清除 SREG
的 I 标志, 因此执行流停在这里之后不再响应任何中断, 效果等同于停机. 一个
被打开却没有处理程序的中断, 表现就是整个系统停止, LED 不再闪烁.
booting.rst 第 3 节讨论的 USB 中断属于这一类.

表的末尾有一条 ``.if`` 检查, 表的字节数不等于 43 x 4 时汇编报错. 漏写或多写
一项会使其后所有向量错位一项, 这类错误在运行时很难定位, 因此在汇编阶段
拦截.


复位入口的各步
==============

``__reset`` 依次执行下列操作.

1. 清零 r1 与 SREG. r1 按 avr-gcc 的约定清零. 写入 SREG 的 0 同时清除了
   I 标志. Caterina 跳转之前已经关闭中断, 这里再次清除, 使启动代码不依赖
   bootloader 的行为.
2. 把 SP 设为 RAMEND, 即 SRAM 的最高地址 0x0aff. AVR 的栈向低地址增长,
   从最高地址开始, 栈可以使用 ``.bss`` 之上的全部 SRAM. 硬件复位时 SP 的
   初值本来就是 RAMEND, 但 Caterina 运行过之后, SP 的值取决于 Caterina
   自身的执行路径.
3. 把 USB 控制器与 PLL 写回复位值. 按下复位键之后, Caterina 会把仍在运行的
   USB 控制器交给应用, 而启动代码无法判断自己经由哪条路径进入. 这五条
   写入的依据见 booting.rst 第 3 节.
4. 把 ``.data`` 从 Flash 复制到 SRAM.
5. 把 ``.bss`` 清零.
6. 调用 main(). main() 通常不返回. 若返回, 启动代码关闭中断, 停在一个
   死循环中.


.data 与 .bss 的初始化
======================

链接器为每个段的边界定义符号, 启动代码据此确定复制与清零的范围. 下表中的
数值取自当前映像, 可在 ``make`` 生成的 leonix.map 中查到:

  ======================  ======  ====================================
  符号                    值      含义
  ======================  ======  ====================================
  ``__data_load_start``   0x042c  ``.data`` 初值在 Flash 中的起始地址
  ``__data_start``        0x0100  ``.data`` 在 SRAM 中的起始地址
  ``__data_end``          0x0102  ``.data`` 在 SRAM 中的结束地址
  ``__bss_start``         0x0102  ``.bss`` 在 SRAM 中的起始地址
  ``__bss_end``           0x0212  ``.bss`` 在 SRAM 中的结束地址
  ======================  ======  ====================================

avr-nm 等工具把 SRAM 地址显示为 0x800100 一类的值. 其中的 0x800000 是
GNU 工具链为区分 SRAM 与 Flash 而加的偏移, 处理器本身看到的地址是 0x0100.

AVR 采用哈佛结构, Flash 与 SRAM 是两个独立的地址空间. 普通的 ``ld`` 指令
只能读取 SRAM, 读取 Flash 需要专用的 ``lpm`` 指令. 复制循环因此用
``lpm r0, Z+`` 从 Flash 取出一个字节, 再用 ``st X+, r0`` 写入 SRAM. ``lpm``
经由 16 位的 Z 寄存器寻址, 只能到达 Flash 的前 64 KiB. ATmega32U4 的 Flash
为 32 KiB, 全部处于这一范围之内; Flash 更大的器件, 例如 ATmega2560, 需要
改用 ``elpm``.

两个循环都先跳到比较指令, 再进入循环体. 起止地址相等时, 即段为空时, 循环体
一次也不执行.

当前映像的 ``.data`` 只有 2 字节, 即 blink_half_period. 这个变量被有意写成
可修改的全局变量, 使 ``.data`` 不为空, 复制循环出错时 L LED 的闪烁间隔
随之出错, 错误因此可以被观察到. 提交 b56d672 记录了这项检验在板子上通过.
``.bss`` 的清零没有单独检验. 调度器依赖 ``nr_tasks`` 等 ``.bss`` 变量的
初值为 0, 调度器在板子上正常运行 (b6a4e86), 可以视为对清零循环的间接检验.


为何不用 avr-libc 的启动文件
============================

avr-gcc 默认链接 avr-libc 的 gcrt1.S, 该文件已经完成上述大部分工作. Makefile
以 ``-nostartfiles`` 关闭这一默认, 改用 start.S. 提交 8ef65de 的说明曾以
USB 状态为由, 认为必须自行编写启动代码. 871209f 更正了这一推理: USB 关闭
序列放进 avr-libc 预留的 ``.init3`` 段, 同样会在中断打开之前执行. 改用
start.S 的实际理由是让复位向量到 main() 之间的每一条指令都出自本项目,
阅读 start.S 即可知道 main() 之前发生的全部操作.

不用 gcrt1.S 之后还要处理一处遗留. avr-gcc 编译含有 ``.data`` 的目标文件时,
会自动加入对 ``__do_copy_data`` 的引用, 含有 ``.bss`` 时加入对
``__do_clear_bss`` 的引用. 这两个符号原本由 libgcc 提供, 是放在 ``.init4``
段中的复制与清零循环, 由 gcrt1.S 依次执行各个 ``.init`` 段时运行.
``-nostartfiles`` 之下没有代码跳入 ``.init4``, 而链接器为满足引用仍会把这两段代码放进映像, 共 38 字节, 永远不会被执行. start.S 把自己的两个循环命名为
``__do_copy_data`` 与 ``__do_clear_bss``, 引用由这两个标号满足, libgcc 的
版本就不再被链接进来. 可以在 leonix.map 中确认 ``.init4`` 段为空.

链接器还需要知道 Flash 的可用上限. avr-gcc 的默认链接脚本 avr5.x 按 32 KiB
计算, 而末尾 4 KiB 属于 Caterina. Makefile 用
``--defsym=__TEXT_REGION_LENGTH__=28672`` 把上限改为 28 KiB, 映像超出时
在链接阶段即报错. 不设置该值时, 这一错误要到烧录时才会出现.
