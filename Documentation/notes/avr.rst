======================
ATmega32U4 的设计思路
======================

**AVR** 是 Atmel 于 1990 年代推出的 8 位 RISC 微控制器架构, ATmega32U4 是
其中带 USB 控制器的一款. 本篇讨论 AVR 为什么被设计成现在的样子, 以及这些
设计决定如何约束 Leonix 的代码. 本篇排在本目录的第一篇: 后面各篇里那些
看似奇怪的写法, 例如用 ``lpm`` 复制 ``.data``、手工保存 SREG、关中断读取
jiffies, 大多是本篇所述设计的直接后果.


依据与推断
==========

设计者为什么这样做, 只有设计者自己的陈述才能回答. 本篇的陈述分三类, 文中
逐处标明:

设计者的陈述
  主要出自 Gaute Myklebust 的 *The AVR Microcontroller and C Compiler
  Co-Design* (Atmel Development Center, Trondheim). 文中未注明日期, PDF
  元数据的生成时间为 1997-12-17, 引用的最新文献是 1996 年 5 月的 AVR
  数据手册. 该文由 AVR 开发团队一方撰写, 记录了指令集定型之前所做的
  修改及其理由. 出处见 references/index.rst.

数据手册的陈述
  ATmega16U4/32U4 数据手册 7766J 与指令集手册 DS40002198. 这两份手册说明芯片做了什么, 偶尔说明为什么.

本文的推断
  两类资料都没有给出理由时, 本文依据设计本身推测其理由, 并写明"推断".
  推断可能是错的, 引用时不应当把推断当作设计者的意图.


来历
====

AVR 架构由两名在挪威 NTNU 求学时相识的学生 Alf-Egil Bogen 与 Vegard Wollan
构思, Wollan 的硕士论文是这一架构的起点, 两人随后把设计提交给 Atmel. (经
Paul Rako 在 Atmel 官方博客 2014-08-21 一文中转述 Wollan 的访谈视频, 视频
原文未核对.) Myklebust 一文的署名单位是 Atmel 位于 Trondheim 的开发中心.

同一系列的 2014-08-21 与 2014-08-25 两文转述了 Wollan 对动机的说明: 当时
开发微控制器程序, 要用带石英窗的陶瓷封装芯片, 每次修改程序都要把芯片取下,
在紫外灯下照射约 20 分钟才能擦除; 基于 Flash 的微控制器可以反复编程, 芯片
留在电路上即可进行, 重新编程只需几秒. (同上, 经转述.) Leonix 的每次 ``make flash`` 都依赖这一点: 程序经 USB 由板上的
bootloader 直接写入 Flash, 芯片始终留在板上.

Myklebust 一文给出了另一个贯穿始终的目标: AVR 从一开始就以 C 语言为目标
设计. 为此 Atmel 在架构与指令集定型之前, 就请瑞典 IAR Systems 的编译器
开发者开始编写 C 编译器, 并按他们的意见修改指令集. 下文各节的大部分
设计都可以追溯到这个目标.


32 个寄存器与单周期执行
=======================

AVR 的核心是 32 个 8 位通用寄存器 r0 至 r31. 在一个时钟周期内, CPU 可以从
中任取两个送入 ALU, 完成运算, 再把结果写回任一寄存器 (Myklebust; 数据手册
4.5 节). 取指与执行重叠进行, 执行一条指令的同时预取下一条, 因此大多数指令
只需一个周期, 每 MHz 约可执行 100 万条指令 (数据手册 4.2 节).

以 Atmel 当时同样生产的 8051 为对照, 8051 的大多数算术指令以累加器 A 为
一个操作数, 运算前后常要在 A 与其他位置之间搬运数据. 32 个寄存器使编译器可以把局部变量与函数参数直接放在寄存器里.
avr-gcc 的调用约定就是这样做的: blink_l() 调用 get_jiffies() 时, 32 位的
返回值放在 r22 至 r25 中, 不经过内存.

这一设计也有代价, Leonix 的上下文切换直接承担这一代价. 寄存器越多, 一个任务的
状态就越大. 上下文切换必须保存全部 32 个寄存器与 SREG, 其中 66 次
``push`` 与 ``pop`` 就占 132 个周期, 是切换开销的六成 (见 scheduler.rst).
Myklebust 一文讨论的全是编译后代码的效率, 没有提到多任务切换. 本文推断:
AVR 面向的是单一程序直接运行在芯片上的场合, 切换代价不在设计者的主要
考虑之内.


哈佛结构
========

AVR 采用**哈佛结构** (Harvard architecture): 程序存储器 (Flash) 与数据
存储器 (SRAM) 是两个独立的地址空间, 各有自己的总线. 数据手册 4.2 节给出的
理由是最大化性能与并行性: 取下一条指令与当前指令读写数据可以同时进行,
上一节的单周期执行依赖于此.

代价是两个空间不能用同一种指令访问. 普通的 ``ld`` 只能读 SRAM, 读 Flash
要用专门的 ``lpm``. C 语言假定只有一个地址空间, 指针只是一个地址, 而在 AVR
上地址 0x0100 既可能指 SRAM 中的变量, 也可能指 Flash 中的一个字节. 由此
产生了下列后果:

- 有初值的全局变量必须在启动时从 Flash 复制到 SRAM, 复制循环必须用
  ``lpm`` (见 boot.rst).
- 常量字符串默认也被复制到 SRAM, 占用总共只有 2.5 KiB 的 SRAM. 要使常量字符串留在
  Flash 中, 需要 avr-libc 的 ``PROGMEM`` 与 ``pgm_read_byte()`` 一类
  专用写法. Leonix 将来为液晶屏输出字符串时会用到这一点.
- GNU 工具链给 SRAM 地址加上 0x800000 的偏移, 以便在链接时区分两个空间,
  avr-nm 显示的 0x800100 即由此而来.


三个指针寄存器
==============

r26 至 r31 两两组合, 构成三个 16 位指针 X、Y、Z, 用于间接寻址 (数据手册
4.5.1 节). Myklebust 一文记录了这三个指针的由来, 这是设计者陈述得最具体的一处:

- 最初只有两个指针. 编译器必须把其中一个专用作软件栈指针, 只剩一个供普通使用. 从一块内存复制到另一块时, 只有一个指针时, 须在源与目的之间反复重新装载. 于是增加了第三个指针 X, 功能较另外两个少.
- 带位移的间接寻址, 即 ``ldd r, Y+q``, 最初的位移上限为 16, 往往不能满足实际程序的需要. 为腾出指令编码空间, 删去了一种分页直接寻址方式, 把位移扩大到 64.

这两项修改在 Leonix 中都有直接的体现. start.S 复制 ``.data`` 的循环是::

  1:  lpm  r0, Z+
      st   X+, r0

Z 指向源, X 指向目的, 两者各自后增, 与 Myklebust 一文为说明第三个指针
而举的复制循环几乎相同. 而 avr-gcc 把 Y 用作栈帧指针: blink_l() 的
反汇编中, ``next_toggle`` 存放在栈上, 用 ``std Y+1`` 至 ``std Y+4`` 写入,
用 ``ldd`` 读出. X 不支持位移寻址 (指令集手册中 ``ldd`` 只有 Y 与 Z 两种
形式), 即上面所说的"功能较少".


两字长的直接寻址
================

删去分页直接寻址之后, 访问一个全局变量就必须先装载指针, 一个字符要用三条
指令共 6 字节. Myklebust 一文据此增加了 ``lds`` 与 ``sts``: 指令本身携带
16 位地址, 占两个字长, 一条指令即可访问 64 KiB 内的任一地址.

该文同时指出, 一次访问的字节越多, 直接寻址的代价越高. 该文举的例子是读取一个
32 位整数: 直接寻址要 4 条 ``lds``, 共 16 字节; 用指针加位移只要 12 字节.
timer_interrupt() 递增 jiffies 时, avr-gcc 生成的恰好是 4 条 ``lds`` 与
4 条 ``sts``. 这 4 条 ``lds`` 也是 jiffies 读取会被中断撕裂的根源: 一次
32 位读取由四条独立的指令完成, 中断可以发生在任意两条之间 (见 tick.rst).


多字节运算
==========

8 位 CPU 处理 16 位或 32 位数时, 要拆成若干次 8 位运算, 低字节先算, 进位
传给高字节. ``adc``、``sbc`` 一类带进位的指令是所有 8 位 CPU 的共同做法.
Myklebust 一文记录了 AVR 在此之外做的三项修改:

零标志的传递
  比较两个 32 位数是否相等, 须检查四次减法的结果是否全为 0. 如果 Z 标志
  只反映最后一次减法, 高字节相等就会被误判为整个数相等. AVR 让 ``sbc``
  与 ``cpc`` 在结果为 0 时保留原来的 Z, 不为 0 时清除 Z (指令集手册中
  两条指令的 Z 一栏). 这样, 四次运算之后的 Z 就是整个 32 位结果的 Z.

带进位的立即数减法
  指令编码空间不够同时容纳带进位与不带进位的立即数加法与减法. 加 K 等于
  减 -K, 于是只保留减法, 把原计划的 ``addi`` 换成 ``sbci``. AVR 至今没有
  立即数加法指令, avr-gcc 生成的 ``subi r24, 0xFF`` 实际上是加 1,
  schedule() 的反汇编中就有这一条.

带进位的比较
  ``cpc`` 只比较, 不写回结果, 比较多字节数时不必先复制操作数.

start.S 的复制循环用两条指令判断 16 位地址 X 是否到达 ``__data_end``::

  cpi  r26, lo8(__data_end)
  ldi  r24, hi8(__data_end)
  cpc  r27, r24
  brne 1b

``brne`` 依据的 Z 标志综合了低字节与高字节两次比较, 这正是零标志传递的
用途. 若 Z 只反映 ``cpc``, 只要地址的高字节相等, 循环就会提前结束.


中断由软件保存现场
==================

中断发生时, AVR 硬件把 PC 压栈, 清除 SREG 的 I 标志, 再跳到向量表中对应的位置, 此外不做其他操作. 状态寄存器 SREG 不被自动保存, 返回时也不被自动恢复,
数据手册 4.4 节与 4.8 节两次强调这一点必须由软件处理.

数据手册没有说明理由. 本文推断: 由软件决定保存什么, 可以只保存处理程序
实际用到的东西. avr-gcc 的 ``ISR()`` 正是按此生成序言, 一个只修改一个
变量的中断可能只保存两三个寄存器, 硬件统一保存全部寄存器则做不到这一点.
对上下文切换而言结果正好相反: 切换要保存的是全部状态, 硬件不提供相应的支持,
switch.S 只能逐条 ``push``.

下列规则直接影响 Leonix:

- 中断标志在 I 清除期间会被记住, I 重新置位后按优先级依次处理 (数据手册
  4.8 节). time_init() 因此要先清除可能遗留的 OCF1A 标志, 见 tick.rst.
- 从中断返回之后, CPU 总会先执行主程序的一条指令, 才响应下一个挂起的
  中断 (同节). 对调度器而言, 这意味着一个任务被切换进来之后至少前进
  一条指令, 即使中断源一直挂起, 任务也不会完全停滞.


8 位总线上的 16 位寄存器
========================

AVR 的数据总线是 8 位的, 读写一个 16 位值需要两次访问. 两次访问之间若被
中断打断, 读到的高低字节可能分属两个时刻. 设计者对此的处理并不统一, 这一
点对编写正确的代码最为重要.

定时器的 16 位寄存器有硬件保护. 每个 16 位定时器有一个 8 位的临时寄存器
TEMP: 读低字节时, 高字节在同一周期被存入 TEMP, 随后读高字节得到的是 TEMP
中的值; 写入时先写的高字节暂存于 TEMP, 写低字节时两者在同一周期写入.
数据手册 14.2 节据此称这类访问是原子的, 并规定读时先读低字节, 写时先写
高字节. 用 C 编写时编译器会遵守这一顺序. 例外是中断处理程序也访问同一
定时器的 16 位寄存器时, TEMP 会被中断改写, 此时主程序仍需关闭中断.

栈指针 SP 没有这种保护. SP 由 SPL 与 SPH 两个独立的 8 位寄存器组成 (数据手册
4.6 节), 两次写入之间 SP 是一个无意义的值. switch.S 的 ``load_sp`` 因此
只在中断关闭时使用.

SRAM 中的普通变量也没有这种保护. jiffies 是 SRAM 中的 32 位变量, 读取需要
4 条 ``lds``, get_jiffies() 只能用关中断的办法保证读取完整.

本文推断: TEMP 机制只用在硬件自己会改变的寄存器上. 定时器的计数值每个
时钟都在变, 不加保护就无法正确读取; SP 与普通变量只在程序写入时才改变,
何时允许打断可以交给软件安排.


写 1 的含义
===========

AVR 对"写 1"另有规定, 初次接触时往往令人困惑:

- 中断标志寄存器中, 向一位写 1 是清除该标志, 写 0 没有作用. TIFR1 中的
  OCF1A 就是这样 (数据手册 4.8 节, 14.10.19 节).
- 向 PINx 写 1 是翻转 PORTx 的对应位, 写 0 没有作用 (数据手册 10.2.2 节).

两条规定的共同点是写 0 无效. 程序可以写入一个只有目标位为 1 的字节, 其余
位一律不受影响, 无需先读出原值. 数据手册没有说明这样设计的理由. 本文推断
其目的在于避免读改写: 先读、再改、再写回的三步之间, 硬件可能置位了另一个
标志, 写回时会把该标志一起清除或改写. gpio.rst 记录了 PINx 上读改写出错的
具体情形.

数据手册 10.1 节则明确说明了另一项相关设计: ``sbi`` 与 ``cbi`` 指令可以单独
改变一个引脚的方向或输出, 不影响同一端口的其他引脚. 单条指令执行期间
不会被中断打断, 因此 ``DDRC |= 1 << DDC7`` 这样只设一位的写法在多任务
之下也是安全的.


对编写代码的影响
================

上面各节可以归纳为编写 Leonix 代码时的几条规则:

- 多于 8 位的变量, 若中断与任务都会访问, 读写都要在关中断状态下进行.
  定时器的 16 位寄存器例外, 硬件已保证其原子性.
- 修改中断标志或翻转引脚时, 直接写入只含目标位的字节, 不用 ``|=``.
- 只有一位的置位或清零可以用 ``|=`` 与 ``&= ~``, 两者编译为单条 ``sbi``
  或 ``cbi``. 涉及多位时, 若别的任务或中断也会修改同一寄存器, 需要
  关闭中断.
- Flash 中的常量要用 ``lpm`` 读取, C 中对应 avr-libc 的 ``pgm_read_*``.
- 中断处理程序若手工编写, 必须自行保存 SREG, 并在调用 C 函数之前把 r1
  清零.
- 每增加一个任务, 就增加 35 字节的切换现场与一块栈, 2.5 KiB 的 SRAM
  决定了任务数的上限.
