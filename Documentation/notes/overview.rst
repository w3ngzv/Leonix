====
总览
====

**Leonix** 是运行在 Arduino Leonardo (ATmega32U4) 上的一个类 Unix 内核, 其
程序接口与分层仿照 Linux. 本篇说明系统由哪几层组成、各层如何配合, 以及每
一部分的详细说明位于哪一篇. 其余各篇按开发顺序写成, 每篇只讲一个机制, 初次
阅读者宜从本篇开始.


分层
====

系统自下而上的各层:

- 硬件: ATmega32U4, 16 MHz, Flash 32 KiB, SRAM 2.5 KiB, EEPROM 1 KiB, 以及
  板上的 USB 接口与外接的 I2C 液晶屏.
- 内核的任务与驱动: 1 ms 的节拍驱动抢占式轮转调度器, 三个任务分别负责液晶屏、
  USB 与用户空间. 驱动包括 I2C、液晶屏、USB 与 EEPROM.
- 文件: VFS 把四个文件系统并入同一个路径命名空间. /dev 是字符设备, /proc
  是内核状态的文本, /bin 是 Flash 中的只读文件系统 romfs, 其余路径属于
  EEPROM 上的 lxfs.
- 虚拟机: 内核中的解释器执行用户程序, 检查每一次访存, 程序只能经由系统调用
  请求内核代为访问文件与设备.
- 用户程序: sh 与全部命令, 例如 ls、cat、ps, 都是虚拟机的字节码程序.

芯片没有 MMU, 也没有特权级, 用户空间与内核之间的边界由虚拟机以软件维持.
内核本身与驱动是原生代码, 不受这一边界保护. 详见 vm.rst.


任务
====

  =====  ==============  =============================================
  编号   任务            职责
  =====  ==============  =============================================
  0      ``lcd_task``    液晶屏每秒刷新状态, 报告栈余量的新低
  1      ``usb_task``    USB 控制请求、串口收发与日志输出
  2      init            运行 /bin/sh, 退出后重新运行
  id     空闲任务        无事可做时使 CPU 进入 Idle 模式
  =====  ==============  =============================================

任务的编号即 ``ps`` 与 ``/proc/tasks`` 中的 ID. 闪烁 L 与 TX 两个 LED 的
任务已在提交 49b3f9b 中删除, 两个 LED 只在 ``panic()`` 时点亮, 见 gpio.rst. 调度、睡眠与等待队列见
scheduler.rst, 液晶屏见 lcd.rst, USB 见 usb.rst.


一条命令经过的路径
==================

在终端中键入 ``ls /dev`` 并回车, 数据依次经过下列各处:

1. 电脑把按键作为 bulk OUT 包发到 USB 端点 2. 端点中断屏蔽自身并唤醒
   ``usb_task``, 后者把字节移入 32 字节的接收缓冲区 (usb.rst, shell.rst).
2. init 任务中的 sh 此前已执行 read 系统调用, 正在终端行规程中等待.
   行规程逐字节回显, 处理退格, 收到回车后把整行交给 sh (shell.rst).
3. sh 把一行切分为 ``ls`` 与 ``/dev`` 两个参数, 以 exec 系统调用运行 ls.
   内核在 romfs 中打开 /bin/ls, 在同一任务中启动第二台虚拟机 (vm.rst).
4. ls 以 open 与 readdir 系统调用列出 /dev. VFS 按挂载点把路径交给字符设备
   表, 后者列出 ttyACM0 (vfs.rst).
5. ls 以 write 系统调用写到 1 号描述符, 即 /dev/ttyACM0. 行规程把 ``\n``
   改为 CR LF, 字节进入 64 字节的发送缓冲区, ``usb_task`` 把这些字节经端点 3
   发回电脑.
6. ls 退出, exec 返回, sh 写出提示符, 再次等待下一行.

整个过程中只有 init 任务执行用户程序, 其余任务照常按节拍轮转. ls 与 sh 共用
init 任务的栈, 两台虚拟机的状态是静态分配的.


存储空间
========

以下数字取自 2026-10-11 删除 LED 任务之后的映像 (提交 49b3f9b, avr-gcc
9.5.0).

Flash 的应用区为 28672 字节, 其余 4 KiB 属于 Caterina bootloader. 映像的
text 为 24644 字节, data 的初值 174 字节, 余 3854 字节. 其中占用较多的部分:

  =====================  ========  ==============================
  部分                   字节      代码
  =====================  ========  ==============================
  /bin 的 12 个程序      4752      fs/romfs_image.c, 编译时生成
  USB                    2384      arch/avr/usb.c
  虚拟机解释器           2244      kernel/vm.c
  lxfs                   2072      fs/lxfs.c
  exec 与系统调用        1386      kernel/exec.c
  VFS                    1378      fs/vfs.c
  格式化函数             1180      lib/vsprintf.c
  /proc                  1108      fs/procfs.c
  =====================  ========  ==============================

SRAM 共 2560 字节 (0x0100 至 0x0aff), 布局见 vfs.rst 的"腾出 SRAM"一节:

- 0x0100 至 0x066a: .data 与 .bss, 共 1387 字节. 其中较大的是两台虚拟机的
  状态与代码文件 464 字节、内核日志 256 字节与空闲任务的 72 字节栈.
- 0x066b 至 0x07ff: 启动栈, 复位后的 ``main()`` 与 ``panic()`` 使用.
- 0x0800 与 0x0801: Caterina 的 boot key, 不属于任何变量或栈.
- 0x0802 至 0x0aff: .noinit 中的三块任务栈, USB 224 字节、init 318 字节、
  液晶屏 224 字节, 共 766 字节, 已无余量.

EEPROM 的 1 KiB 全部属于 lxfs, 其中元数据与日志 352 字节, 文件内容可用 672
字节.

SRAM 是限制后续功能的主要因素. 每增加一个并发运行的程序, 都需要一台虚拟机
的状态与一块栈, 而 .bss 末尾距 boot key 为 405 字节.


三个仓库
========

  ===================  ===================================  =================
  仓库                 内容                                 位置
  ===================  ===================================  =================
  Leonix               内核, 包括虚拟机的解释器             本仓库
  Leonix_toolchain     汇编器 lxasm.py, 上传工具 lxput.py   external/toolchain
  Leonix_coreutils     sh 与全部命令的源码                  external/coreutils
  ===================  ===================================  =================

两个外部仓库以 git 子模块的形式检出, 各自固定在内核最后一次构建与测试时的
提交上. 内核编译时以汇编器编出 Leonix_coreutils 的程序, 再打包为 /bin. 构建
步骤见 building.rst, 三者的分工与理由见 vm.rst.


各篇的内容
==========

- 芯片与启动: avr.rst 说明 ATmega32U4 的设计思路, 包括 32 个寄存器、哈佛
  结构与中断现场的保存; boot.rst 说明复位之后到 ``main()`` 之间启动代码执行
  的各步; gpio.rst 说明引脚的三个寄存器与板上的 LED; tick.rst 说明 1 ms 的
  系统节拍与 jiffies.
- 内核与驱动: scheduler.rst 说明任务切换、睡眠、等待队列、栈的预算与实测,
  以及节拍中断的周期数; lcd.rst 说明 I2C 总线、液晶屏与断线恢复; printk.rst
  说明格式化函数与内核日志; usb.rst 说明 USB 虚拟串口与免按复位键烧录.
- 文件与用户空间: shell.rst 说明字符设备与终端行规程; vfs.rst 说明 VFS、
  文件描述符、lxfs 与 /bin; vm.rst 说明虚拟机、系统调用、exec、/proc 与
  从电脑写入程序.

板子开机之后由 Caterina 交给应用的机器状态见 booting.rst, 外部文献见
references/index.rst.
