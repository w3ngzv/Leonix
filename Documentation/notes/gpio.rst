=================
引脚与 LED 的控制
=================

**通用输入输出** (General Purpose Input/Output, GPIO) 是可以由程序设为输入
或输出、并读写其电平的芯片引脚. ATmega32U4 的 GPIO 按 8 个一组编为端口
B 至 F, 每个引脚记作端口字母加位号, 例如 PC7 是端口 C 的第 7 位. Leonix
目前只用 GPIO 驱动板上的 LED, 相关代码在 init/main.c. 依据是数据手册
10.2 节.


三个寄存器
==========

每个端口由三个 8 位 I/O 寄存器控制, 寄存器的第 n 位对应该端口的第 n 个引脚:

DDRx (Data Direction Register)
  该位为 1 时引脚是输出, 为 0 时是输入. 复位后全部为 0, 即全部引脚都是
  输入, 不会意外驱动外部电路.

PORTx
  引脚为输出时, 该位决定输出高电平还是低电平. 引脚为输入时, 该位为 1
  表示打开内部上拉电阻.

PINx
  读取时得到引脚上的实际电平. 写入 1 会翻转 PORTx 中对应的位, 写入 0
  没有作用 (数据手册 10.2.2 节).

点亮一个接在 PC7 上的 LED, 需要先把 DDRC 第 7 位置 1, 使 PC7 成为输出,
再把 PORTC 第 7 位置 1, 使 PC7 输出高电平.


板上的 LED
==========

Leonardo 有三个可由程序控制的 LED, 引脚与点亮电平见 booting.rst 第 4 节:

  ======  ====  ===========
  LED     引脚  点亮电平
  ======  ====  ===========
  L       PC7   高
  TX      PD5   低
  RX      PB0   低
  ======  ====  ===========

TX 与 RX 在低电平时点亮, 即 PORTD 第 5 位写 0 时 TX 亮. 该极性取自
Caterina.h 的定义, 尚未在板子上实测. init/main.c 只翻转 LED, 不关心哪一种
电平对应点亮, 因此不受极性影响.


main.c 中的写法
===============

blink_l() 开始时执行::

  DDRC |= 1 << DDC7;

DDC7 的值是 7, ``1 << DDC7`` 即 0x80, 只有第 7 位为 1. ``|=`` 保留 DDRC
其余各位, 只把第 7 位置 1. 之后每到时间执行一次::

  PINC = 1 << PINC7;

该语句向 PINC 写入 0x80, 只有第 7 位为 1, PORTC 第 7 位因此翻转: 原来输出低
电平就变为高电平, 原来高就变为低. 其余各位写入的是 0, 不受影响. 用 PORTC
实现同样的翻转需要先读出、取反、再写回; 写 PINC 只需一次写入, 也不必
记住 LED 当前的状态.

这里写作 ``=`` 而不写作 ``|=``, 原因在 PINx 的读取与写入含义不同. 下面三种
写法用 avr-gcc 9.5.0 以 -Os 编译的结果如下:

  ===================================  ===================  ==================
  C 代码                               生成的指令           效果
  ===================================  ===================  ==================
  ``PINC = (1 << 7) | (1 << 6);``      ``ldi``, ``out``     翻转第 6、7 位
  ``PINC |= 1 << 7;``                  ``sbi``              翻转第 7 位
  ``PINC |= (1 << 7) | (1 << 6);``     ``in``, ``ori``,     翻转第 6、7 位,
                                       ``out``              以及读取时为高的
                                                            其余各位
  ===================================  ===================  ==================

第三种写法先用 ``in`` 读取 PINC, 得到的是全部引脚的电平, 再与 0xc0 相或
写回. 端口 C 中凡是当时为高电平的引脚, 对应位都会被写入 1, 随即被翻转.
第二种写法碰巧正确, 原因是只设一位时编译器改用单条 ``sbi`` 指令, 而数据
手册 10.2.2 节说明 ``sbi`` 作用于 PINx 时只翻转该位. 正确与否取决于编译器
选择了哪条指令, 这样的代码不宜依赖, 因此 main.c 统一写作 ``=``.


与调度器的关系
==============

各任务都可能在任意两条指令之间被切换出去. 若两个任务修改同一个端口, ``in``,
``ori``, ``out`` 这样分三步完成的读改写就可能在中途被打断: 任务 A 读出 PORTD,
任务 B 修改 PORTD, 任务 A 再把旧值改写后写回, B 的修改随之丢失.

端口 D 现在确实由两个任务共用. blink_tx 写 PIND 翻转 PD5 上的 TX LED,
液晶屏任务的 I2C 驱动则修改 PD0 与 PD1: 打开内部上拉,
以及总线停滞时用这两个引脚手工发出时钟. arch/avr/i2c.c 因此规定, 对 PORTD 与
DDRD 的每次修改都只涉及一位, 由编译器生成单条 ``sbi`` 或 ``cbi``.
一条指令执行期间不会被中断打断, 这样的修改不会与其他任务的修改相互覆盖. 用
``avr-objdump -d arch/avr/i2c.o`` 可以确认其中没有对 0x0a (DDRD) 与 0x0b (PORTD)
的 ``in`` 或 ``out``.

需要同时修改多位时, 读改写必须在关闭中断之后进行.
