====================
上下文切换与轮转调度
====================

实现细节
========

每个任务有自己的一块栈(128 字节), 保存它被打断时的全部状态. Timer1 每 1 ms
触发一次中断, arch/avr/switch.S 依次做四件事:

1. 把当前任务的 32 个寄存器和 SREG 压进它自己的栈.
2. 把此刻的栈指针存进 current->sp.
3. 调用 schedule(), 把 current 换成下一个任务. 这就是轮转, 两个任务就
   0, 1, 0, 1 交替, 没有优先级.
4. 从新任务的 current->sp 恢复栈指针, 弹出它上次保存的寄存器, reti 返回.

返回的时候, CPU 已经身处另一个任务被打断的位置. 对每个任务来说, 它只是被
暂停了 1 ms, 完全感觉不到切换. 新建的任务从没运行过, 没有保存过的现场,
所以 task_create() 事先在它的栈上伪造一份, 让第一次切换到它时, 看起来像是
从中断返回到了任务函数的开头.

两个任务
========

两个任务就是 init/main.c 里的 blink_l 和 blink_tx, 前者每 0.5 秒翻转一次
L 灯, 后者每 0.125 秒翻转一次 TX 灯. 两个都是死循环, 不停地查询 jiffies
有没有到时间, 从不主动让出 CPU. 这样写是故意的, 如果没有抢占, 第一个任务
会永远占着 CPU, 第二个灯根本不会闪. 两个灯都在闪, 就证明了切换是由中断
强制完成的.

与 Arduino 写法的比较
=====================

Arduino C 的标准写法::

    void loop() {
        if (millis() - t1 >= 500) { t1 += 500; toggle(L); }
        if (millis() - t2 >= 125) { t2 += 125; toggle(TX); }
    }

没有任务, 没有栈, 没有汇编, 几行就够了, 也没有切换的开销.

现在这个版本反而很浪费. 两个任务都在空转等待, 各自占 50% 的 CPU, 99% 的
时间都在反复读 jiffies. 真正的内核里, 任务应该调用类似 sleep(500) 的函数,
在等待期间把 CPU 交出去, 这正是下一步要做的.

抢占式调度的价值, 要到任务不再这么简单时才显现出来. 比如一个任务在解析
网络包, 要算 30 ms, 同时 PS/2 键盘每隔几十微秒送来一位数据, LCD 也要刷新.
用 loop() 写, 每个功能都得手动拆成一小段一小段的状态机, 任何一处写成阻塞,
其他功能就全部停住. 有了调度器, 每个任务都能按直线逻辑写, 阻塞了也只影响
它自己, CPU 的分配交给调度器. 代价就是现在这些: 每个任务一块栈(SRAM 只有
2.5 KiB), 每 1 ms 一次切换, 约 10 微秒.
